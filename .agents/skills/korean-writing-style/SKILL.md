# Korean Writing Style

## 적용 대상

사람이 읽는 한국어 전체에 적용한다. 사주빛 고객용 해석과 목차, 웹 UI, 책 원고, 강의안, SNS, 마케팅 문구, 메일, README, PR과 이슈를 포함한다. 코드, 프로토콜 필드, JSON 키, 인용한 원문, 파일 경로와 기술 식별자는 변경하지 않는다. 지시문서의 목록과 헤딩 구조는 유지하되, 설명 문장은 자연스러운 한국어로 작성한다.

## 최우선 원칙

1. **사실과 해석 근거를 보존한다.** 문장을 자연스럽게 바꾸려고 명리 계산값, 용신 판단, 관계, 성격 적중률, 고객의 실제 경험을 지어내지 않는다.
2. 사람이 실제로 쓰는 동사와 형용사로 말한다. 피동 중복, 번역한 듯한 명사 나열, 추상적인 선언을 피한다.
3. 동의어 반복, 불필요한 수식어, 인위적인 대조와 결론 문장을 줄인다. 짧은 문장과 긴 문장을 적절히 섞는다.
4. 과장 없이 단정할 수 있는 사실은 분명히 쓰고, 검증되지 않은 심리와 미래 사건은 단정하지 않는다. 같은 문단에서 완곡 표현을 겹쳐 쓰지 않는다.
5. 고객에게 보여 주는 명리 해설은 계산 설명부터 늘어놓지 않는다. 특징을 먼저 말하고, 발현 상황과 판단 기준, 달라질 수 있는 조건을 이어 쓴다. 명리 근거는 별도의 선택형 설명으로 제공한다.

## 표현 순화

- 박아두다, 박다(값이나 파일을 다룰 때) → 저장하다, 기입하다, 입력하다, 고정하다.
- 박힌 상태 → 저장된 상태, 적용된 상태.
- 갈아끼우다 → 교체하다, 바꾸어 넣다.
- 파일이나 프롬프트를 던지다 → 첨부하다, 전달하다, 입력하다.
- 때려박다 → 한 번에 입력하다, 일괄 등록하다.
- 도구를 깔다 → 설치하다.
- 판단 순서나 관점을 뒤집다 → 순서를 바꾸다, 반대로 보다, 다시 정하다.

위 표현을 문자 그대로의 실제 물리 행동을 뜻할 때까지 기계적으로 바꾸지는 않는다.

## 번역투와 상투구

- 이중 피동을 없앤다. 판단되어진다 → 판단된다. 보여집니다 → 보입니다.
- 목적어를 직접 받는 동사를 활용한다. 규제에 대해 논의하다 → 규제를 논의하다.
- '~을 통해', '~에 있어서', '~의 관점에서'를 습관적으로 사용하지 않는다. 데이터를 분석해, 이 문제에서처럼 직접 쓴다.
- 추상 명사에 '가지고 있다'를 붙이기보다 동사나 형용사로 표현한다. 경쟁력이 강하다처럼 간결하게 쓴다.
- '에 의해 생성된'보다 'AI가 만든'처럼 실제 행위자를 밝힌다.
- '~로의', '~으로부터의', '~와의 대비' 등 부자연스러운 명사구를 풀어 쓴다.
- 직역한 비유를 피한다. '다음 걸음', '가능성의 토대를 마련', '문제를 녹여 버리다', '질문을 던지다' 등을 문맥에 맞는 직접적인 표현으로 고친다.
- '이 결과가 시사하는 바가 큽니다', '혁신적인 방식', '주목할 만한 변화', '결론적으로', '요약하면 두 가지입니다' 같은 상투적인 도입이나 결론을 쓰지 않는다. 구체적 발견이나 행동을 바로 쓴다.
- '~라는 점에서', '~라는 뜻입니다', '~한 것입니다'로 끝내는 문장을 줄인다. 문장의 실제 주어와 동사를 살린다.
- 같은 문단에 접속사를 반복하거나 '매우', '굉장히'를 근거 없이 사용하지 않는다.

## 문장부호

- 한국어 고객용 글에서는 em dash(U+2014) 금지.
- 가운데점(U+00B7) 금지. 대신 쉼표, '와/과', 괄호, 콜론을 문맥에 맞게 사용한다.
- en dash(U+2013)는 숫자나 영문 범위를 표기할 때만 사용하고, 그 외에는 문장을 나눈다.
- 원본 인용, 식별자, 코드 또는 외부 자료의 문자까지 임의로 변조하지 않는다. 고객용 제목과 본문에는 위 규칙을 적용한다.

## 사주빛 해석에서 추가로 확인할 것

1. **문장의 자연스러움과 사실성은 별개 검사다.** 스타일을 고쳤다고 성격 예측이 더 정확해졌다고 표시하지 않는다.
2. 해석 가설을 행동의 실제 기록처럼 서술하지 않는다. 구체적인 생활 장면을 제시할 때도 예시인지 분명히 구분한다.
3. 한 명식의 같은 핵심 특징을 여러 장에서 표현만 바꿔 반복하지 않는다.
4. 독립 근거가 부족한 심리 동기, 타인의 속마음, 건강 상태, 임신 결과, 부의 크기 등은 만들어내지 않는다.
5. 인물의 특징을 말하는 본문은 자연스러운 존댓말을 사용한다. '월지의 정관은~' 같은 근거 설명은 고객이 펼치는 상세 분석으로 분리한다.
6. 목차는 짧고 동일한 문법을 사용한다. 같은 위계의 제목에 질문형과 문장형, '~할 때'와 '~분석'을 무분별하게 섞지 않는다.


## AI처럼 보이는 자기해설 말투 방지

- 고객에게는 해석이 어떻게 만들어졌는지 설명하기보다, 해당 행동이 나타날 수 있는 상황을 먼저 묘사한다.
- 고객용 본문에서 `이 해석은`, `이 장에서는`, `풀이할 수 있습니다`, `이런 뜻은 아닙니다` 같은 글 자체에 관한 설명을 사용하지 않는다. 별도 편집자 검토 메모로 옮긴다.
- `수 있습니다`, `수도 있습니다`가 문장마다 반복되면 문장을 합치거나 실제 조건을 먼저 제시한다. 반복을 없애려고 검증되지 않은 성격을 사실로 단정해서는 안 된다.
- `중요한 것은`, `다른 셈입니다`, `같은 사람이라도`처럼 내용이 없는 마무리 문장을 삭제한다. 한 문단은 새로운 행동, 조건 또는 판단 기준을 적어도 하나 설명해야 한다.
- 제목과 원래 행동 후보가 맞지 않으면 문체로 해결하지 않는다. 제목이나 후보를 재검토한다.
- 단순 금지어 검사는 초벌 검수다. 사람이 10개 항목을 연속으로 읽고 소재와 문장 끝이 반복되는지도 확인한다.

## 완료 전 확인

- 사용자에게 보여 줄 최종 문장에서 금지 문장부호, 거친 구어, 이중 피동, 명백한 직역 표현을 검사한다.
- 의미가 약해지는 대체 표현은 다시 자연스럽게 고친다.
- 계산 근거, 수치, 해석의 불확실성, 소제목 의미를 보존했는지 확인한다.
- 고객용 해설에서 명리 증거 ID, 내부 변수, 생성 지시가 노출되지 않았는지 확인한다.
- 본문을 읽었을 때 고객이 '나에 대한 설명'을 읽는지, '명리학 교재'를 읽는지 확인한다.
