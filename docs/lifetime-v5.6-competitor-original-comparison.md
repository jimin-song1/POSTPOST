# 사주빛 V5.6 — 음양관·귀신사주 동일 명식 원문 대조의 개발 반영안

> 상태: 비교 분석을 반영한 **후속 설계/구현 명세**. 원본 595장 전수 문장 판독을 새로 수행했다는 뜻이 아니다. 본 문서는 사용자가 제공한 ‘실제 원문 대조’의 관찰값을 근거로 삼으며, 기존 V5.6 목차를 변경하지 않는다. 배포 코드는 수정하지 않는다.
> 선행 문서: \`lifetime-v5.6-evidence-map.md\`, \`lifetime-v5.6-interpretation-logic-v3.md\`

## 1. 교차 대조의 해석: 무엇을 사실로 볼 것인가

| 비교 결과 | 관찰된 내용 | 사주빛에서 허용되는 활용 | 잘못된 활용 |
| --- | --- | --- | --- |
| 직업/사업 | 음양관은 검증된 체계의 운영, 귀신사주는 정확성·책임 강조 | 공통 **해석 후보**로 세우고 실제 계산 근거/반례로 검증 | 두 업체가 일치하므로 실제 직업 능력이 증명됐다고 판단 |
| 돈 | 음양관은 편재-부동산·계약·자산, 귀신사주는 직장+부수입 | 재물운의 서로 다른 **수입·자산·거래** 서사 후보로 분리 | 시주 편재=부동산 큰손/부수입 확정 |
| 귀인 | 학교·배움·선생님·교육적 지원, 학당귀인 관련 서사 | 실제 귀인성 판정, 위치, 적용 시기, 활동 환경을 분리 | 귀인성이 있으면 특정 선생님/장소/시기에 도움 확정 |
| 결혼 | 배우자 묘사 구체적이나 실제 상태/상대 근거 부족 | 고객 본인의 신뢰·역할·갈등 반응, 기혼/미혼 분기 | 일지 하나로 실제 남편 성격 확정 |
| 자녀 | 식상 원국 부재와 세운 유입을 임신 확률로 단정 | 원국의 상징/세운의 상징 분리 | 화 0%=임신 불가 또는 화 들어오면 임신 강함 |
| 대운 | 23~32세 무자대운, 2027~36 황금기 33~42세 등 연령식 표기 | 실제 절입 시점/순행·역행/만 나이/세는나이 **체계 명시 후 비교** | 2027=실제 대운 시작일 또는 황금기 증명 |
| 품질 | 귀신사주 텍스트에 \`(기유 도화 true)\` 같은 내부 변수, 출처 없는 직감력 수치 | 내부 디버그 누출·근거 없는 메트릭 검출 | 출처 없는 점수·플래그를 고객에게 그대로 출력 |

**중요**: 같은 명식으로 비슷한 결과를 내는 것은 독립 검증이 아니라 비슷한 해석 관습의 공유일 수 있다. 원국/파생값을 다르게 입력했을 때 설명이 의미 있게 바뀌는지를 별도 테스트한다.

## 2. 새 목표: 답을 꾸미는 '스토리텔러'가 아니라 해석을 선별하는 '판단기'

최종 서술의 단위는 \`claim\`이다. '금이 좋다', '생각이 많다'처럼 단일 키워드로 문단을 만들지 않는다.

\`\`\`
calculated_fact (원국/강약/격국/용신/운)
  -> relationship_rule (왜 두 요소를 함께 읽는지, 어느 방향으로 작용하는지)
  -> claim_candidate (소제목별 서로 다른 해석 가설)
  -> contradictory_signal (조건 또는 반대 해석)
  -> evidence_decision (채택/약화/제외)
  -> narrative_owner (책 전체에서 어떤 소제목이 이 주장을 가장 깊게 다룰지)
  -> customer_story (생활 장면, 장점, 부담, 의외의 면; 글쓰기)
  -> claim_validator (근거·범위·반복·문체 검사)
\`\`\`

### 해석 후보 계약의 최소 데이터 모델

\`\`\`ts
type Candidate = {
  id: string;
  primarySectionId: string;
  claimType: "UPSIDE" | "DOWNSIDE" | "CONTRAST" | "LESS_OBVIOUS" | "DOMAIN_BEHAVIOR";
  claim: string;
  evidenceIds: string[];
  relationRuleIds: string[];
  derivedFromSourceIds: string[];  // 이중 집계 차단
  competingCandidateIds: string[];
  negatingEvidenceIds: string[];
  level: "DIRECT_CALCULATION" | "TRADITIONAL_INTERPRETATION" | "EDITORIAL_EXAMPLE";
  scope: string[];                  // 어느 환경에서 나타나는 해석인가
  cannotClaim: string[];
  narrativeOwnerId: string;
  readiness: "READY" | "CONDITIONAL" | "REJECTED";
  editorReason: string;
}
\`\`\`

이 타입은 구현 제안이며 현재 repository에 이미 존재하는 타입이 아니다.

**검증 단계별 작업 분리:**
- 서버/규칙 기반으로 정해진 사실(원국·십성·용신 분류·점수·운의 기간)만 확정할 것.
- 심리·행동 후보는 전통적 해석 가설이며 **'근거가 있다'와 '실제 사람이 그렇다'는 다름**.
- 모든 심리 후보가 \`relationRuleIds\`를 달도록 하고, 계산 근거를 역추적 가능하게 한다.
- 같은 원본에서 파생된 숫자를 여러 개 인용했다고 근거가 더 확실해진 것처럼 점수화하지 않는다.
- 출처가 불명확한 경쟁사의 90점·55점·직감력 85·꿈선명도 100은 POSTPOST 점수로 가져오지 않는다.

## 3. 동일 원국 테스트 — 실질적으로 달라져야 할 서사

사용자가 POSTPOST 엔진에서 실행해 제공한 값:
- 乙亥 / 乙酉 / 甲子 / 戊辰
- 강약 최종 48.57점, 중화신약. 월령의 관성 관계로 기본 −18; 을목 2개와 통근·득세가 이를 일부 보완
- 선호 오행 수69.92, 화65.48, 목65.00, 토52.95, 금52.22
- 종합 최상위 수, **확정 주용신 없음**(80 미달), 조후는 **정화(丁) → 병화(丙) → 경금(庚)** 우선
- 금은 격국 유지 측면의 우호와 억부 부담이 공존
- 사용자 제공 맥락: 여성, 기혼, 자녀 없음 (이 사실로 실제 임신 상태는 결정할 수 없음)

### 후보 세트: 10개 성격 항목이 모두 같은 얘기를 하지 않도록

| 목차 | 핵심 질문과 주장 후보 | 차별화할 근거 / 필요 보류 |
|---|---|---|
| 01-01 기본 | 사회 규범/자율성의 조화와 마찰 | 월지 정관+연월간 겁재; 강약을 심리적 무기력으로 해석 금지 |
| 01-02 첫인상 | 공적인 태도와 개인적 신뢰 형성의 분리 | 월주와 일주 역할 차이; 실제 낯가림 단정 금지 |
| 01-03 혼자 | 새로운 정보를 받아들이고 생각을 정리하는 모습 | 일지 정인, 수 기운; 불필요한 '고집' 반복 금지 |
| 01-04 속마음 | 생각/표현 간 간격을 관찰할 주제 | 인성/식상 관계와 원국 화의 표현 여부; 화 없음=말 못함 금지 |
| 01-05 결정 | '정확한 정보'와 '기회/위험'의 균형 | 인성과 시간 편재, 정관의 책임; 실제 결정 속도 단정 금지 |
| 01-06 결정 후 | 주장을 지키거나 수정하는 **조건** | 겁재·정인·관성의 반대 작용; 01-05와 다른 사건 |
| 01-07 양보 | 협업, 주도권, 공로 배분, 경계 | 비겁+관성 결합; '무조건 승부욕' 금지 |
| 01-08 난관 | 규칙의 보호/압박 두 면과 대응 | 금의 격국 유지 우호/억부 부담 충돌; '직장운 나쁨' 금지 |
| 01-09 장점 | 정보를 받아들여 책임 있는 결과에 연결하는 능력 | 정인+정관, 강약 보완; 실제 능력 인증 아님 |
| 01-10 단점 | 스스로 설정한 기준과 책임이 과해질 때의 비용 | 정관+비겁+인성; 모든 단점을 완벽주의로 치환 금지 |

**실패**: 10개 항목이 '자기 판단이 분명하지만 남의 말도 듣는다'로 귀결.
**합격 후보**: 각 항목의 '어떤 상황에서 / 왜 / 어떤 차이가 나타나는지'가 서로 달라야 함.

### PART02·03·04·05를 분리하는 근거

- **PART02 직업/학업**: 무엇을 배우고 어떤 기술/업무를 숙련할 때 장점이 있는가 — 인성/관성/식상/격국/오행 정렬
- **PART03 직장**: 조직의 규칙·평가·책임을 받는 자리에서 편안함과 부담이 어떻게 공존하는가 — 정관(금)/겁재/중화신약 및 해당 대운·연운 직장 분야
- **PART04 사업**: 상품/서비스 생산, 고객 응대, 동업, 계약, 권한 분배, 확장의 조건 — 식상/재성/비겁/정관/격국, 용신 + 사업 분야
- **PART05 재물**: **소득 획득, 소비, 저축/보전, 계약, 자산관리** 각각 다른 메커니즘 — 편재만으로 투자/부동산 성과 단정 금지

같은 '정관'을 여러 장에 재사용하는 것은 허용하지만 **동일한 주장과 문단의 재탕은 금지**한다.

### 대표 예시: 같은 원국을 세 PART에서 다르게 풀이하는 법

1. 성격: "규칙 자체를 싫어하는 것보다, 그 규칙이 내 판단과 어떤 관계인지 확인하는 성질" — **규칙/자율의 긴장**
2. 직장: "일에 대한 책임과 역할이 분명하면 기준이 힘이 되지만, 결과에 대한 부담만 남으면 기준이 압박이 되는 방향" — **관성의 양면**
3. 사업: "고객을 상대하고 계약·정산할 때 누가 무엇을 결정하고 책임지는지가 명확해야 할 수 있음" — **비겁·재성·관성의 실제 거래 장면**

셋의 차별성은 주장 자체에 있어야 한다. "자기 기준이 분명하다"로 세 번 끝내지 않는다. 실제 업무/배우자의 행동, 재물 결과를 과거·미래 사실처럼 만들지 않는다.

## 4. 시간계산 특별 검증: 경쟁사 예측 연령 복제 금지

비교 보고서에서 음양관은 \`23~32세 무자대운\`, 귀신사주는 \`2027~2036년 33~42세\`를 제시한다.
- 1995년 9월 30일생은 2027년 **만 나이로 생일 전 31세, 생일 후 32세**, 한국식 세는나이는 33세다.
- \`33~42세\`는 세는나이 기준 표현일 수 있으나, 이로부터 **실제 대운 전환일이 2027-01-01**이라는 결론을 내릴 수 없다.
- POSTPOST의 절입 기준 정확한 대운 시작일/전환일/나이 계산을 source of truth로 사용한다.
- 기간별 운은 \`favorability\` / \`activation\` / 분야별 \`category\`를 분리. 숫자는 시각화할 경우 출처와 산식/내부 모델임을 설명한다.
- 연간 해설은 그해의 세운 외에 대운·월운이 있는 만큼 결합하고, 원국 충합/변화 성립 조건을 따진다.

## 5. 최종 출력 QA — 이번 비교에서 새롭게 추가할 규칙

### 구조 검수
- V5.6 소제목별 narrative ownership 지정.
- 동일 claimId를 무관한 소제목에서 장문 반복 사용하지 않는다.
- 각 소제목의 주요 근거와 경쟁 후보/반대 근거를 내부 기록으로 남긴다.
- 해설은 고객에게 쉬운 존댓말로 직접 이야기하고, 기술 출처는 보조.

### 부정확성 검수
- \`(기유 도화 true)\`, \`배우자 지지 true\`, \`true/false\`, \`undefined\`, \`null\`, \`NaN\`, \`[object Object]\`, 코드 키/JSON 등 내부 정보 누출을 문맥 인식으로 검출; 고객에게 원본 JSON 그대로 노출 금지.
- 스키마 검증뿐 아니라 텍스트 내부에 출처 없는 숫자·기준 없는 퍼센트가 나오는지 검사.
- 현재 자녀 없음과 임신 여부 미확인을 분리.
- 타인의 행동·성격·기존 상처를 일지 하나로 사실처럼 확정하지 않는다.
- 화(식상) 원국 부재 → 임신 불가·임신 특정 시기 확정 금지.
- 금이 격국에 유리하지만 억부에 부담이면 한쪽 서사만 일방적으로 사용하지 않는다.
- 예측에서 **활동이 큼**과 **도움이 됨**을 한 점수로 취급 금지.

### 실제 QA 실험
- 같은 원국, 다른 이름: 해석 핵심 동일
- 같은 원국, 결혼 상태만 변경: 원국/용신/강약 그대로, 가족/관계 서사만 상황 맞춤
- 서로 다른 원국 여러 명: 성격 10개 핵심 주장과 문단의 의미 있는 변화가 확인돼야 함
- 같은 원국, 다른 임의 생활/직업 프로필: 원국 해석을 프로필에 억지로 끼워 맞추지 않음
- 가까운 생일의 월주 전환, 강약 경계, 용신 충돌, 관계 합화 경계 등 케이스를 별도 검증
- 독자 블라인드 평가: 맞음/틀림/애매함/확인 불가 와, 재미/신선함/신뢰/읽기 쉬움 **별도로** 수집. '와!'만 높은 문장은 정확도 통과로 취급하지 않는다.

## 6. 작업 우선순위 (실제 구현 시)

1. 계산 결과의 provenance(원본·파생 연결)를 통일해 중복 집계 예방
2. V5.6 PART01 후보 생성/반대근거 및 섹션 소유권
3. 후보 선정 로직과 사유 기록 (유사한 후보를 구분하지 못하면 기록에서 확인 가능)
4. 실 LLM으로 PART01 10개 작성; 문체는 '단순/명확한 설명'이 아닌 **독립적인 새 발견이 있는 읽을거리**
5. claim-level groundedness/누출/과신/동어반복 검사
6. 동일 출생정보+이름 변경/고객 상황 변화/대조 명식의 블라인드 테스트
7. 이후 직업→사업/재물→관계→귀인→시기 분석 순으로 확장
