# 사주빛 평생사주 V5.6 — 목차별 명리 근거 매핑 (1단계)

> 상태: **설계/근거 연결 명세**. 계산식을 교체하거나 배포 해설을 수정한 문서가 아니다.
> 기준: 2026-10-19 합의된 V5.6 목차, 148p 편집 목표(고정 분량 아님), POSTPOST \`main\`의 \`SajuAnalysis\` / \`ai-interpretation/input-builder.ts\`.
> 목표: 각 소제목마다 **주근거·보조근거·풀이 범위**를 지정하고, AI에게 원국의 계산 결과를 재계산하게 하지 않는다.

## A. 공통 원칙

1. **원국 → 맥락 → 충돌 검토 → 고객 언어** 순서. 이름·생년·고객의 이전 대화를 통해 명식에 없는 사실을 추론하거나, 개인적인 경험을 꾸며내지 않는다.
2. **용신은 만능 해석 키워드가 아니다.** 오행을 어떻게 돕거나 부담을 주는지, 특정 기간의 기운과 원국의 조합을 말해야 할 때만 \`USEFUL_GOD:SYNTHESIS\`와 개별 억부·격국·조후·통관·병약 근거를 사용한다. 성격·연애·가족의 기초 성향은 일간·일주·십성·위치·관계를 먼저 쓴다.
3. **명리 전통의 상징 해석**과 **계산 엔진의 점수**를 분리한다. POSTPOST 가중치는 고유 모델이고 명리학의 절대 수치가 아니다. 높은 활성도=길한 결과가 아니다. \`favorability\`와 \`activation\`을 별도 설명한다.
4. **주근거가 없으면 그럴듯한 문장을 채우지 않는다.** 필요 데이터가 없다면 섹션 생성 중단 또는 범위 축소/조건부 표현.
5. 본문은 인간 역술인이 한 사람을 이해하며 이야기하듯 **변화의 이유·겉과 속의 차이·상황에 따라 달라지는 모습**을 이어 쓴다. 모든 소제목을 \`장점→단점→조언\` 템플릿으로 강제하지 않는다.
6. 재물·승진·합격·혼인·임신·질병·자녀 수/성별·사망·사고를 결정론적으로 단언하지 않는다. 건강은 의학적 판단이 아닌 전통 오행의 생활 맥락으로 제한.
7. 각 섹션은 독립된 결론과 근거가 있어야 한다. **전혀 다른 소제목에 동일한 문단을 재활용하면 실패**로 판정한다.
8. 고객 상태(미혼/연애/기혼, 자녀 유무/양육 상황)는 계산값을 변경하지 않으며, 제목 선택과 화법의 문맥에만 관여한다.

## B. 근거 키 명세 (현재 입력 빌더 기준)

| 약칭 | 현재 evidence ID | 의미 |
|---|---|---|
| N1 | \`NATAL:DAY_MASTER\` · \`NATAL:PILLARS\` | 일간·일주·네 기둥과 위치 |
| N2 | \`NATAL:TEN_GODS\` · \`NATAL:HIDDEN_STEMS\` | 십성의 위치, 지장간 |
| N3 | \`NATAL:FIVE_ELEMENTS:ELEMENT:*\` · \`NATAL:STRENGTH:ADJUSTED\` | 오행별 조정 비율, 일간 강약 |

| N7 | \`NATAL:STARS\` | 판정된 귀인·신살 |
| Y1 | \`USEFUL_GOD:SYNTHESIS:*\` | 종합 용신 요소별 역할·점수·신뢰·충돌 |
| Y2 | \`USEFUL_GOD:EOKBU\` · \`JOHU\` · \`TONGGWAN\` · \`BYEONGYAK\` · \`STRUCTURE\` | 용신 5개 개별 관점 |
| Y3 | \`NATAL:STEM_PREFERENCES\` · \`NATAL:BRANCH_PREFERENCES\` | 천간·지지 선호와 원국 조건 |
| F1 | \`FORTUNE:DAEUN-*:(FAVORABILITY,ACTIVATION,ALIGNMENT,TEN_GOD_FLOW,TAGS,PERIOD_CONTEXT)\` | 기간별 도움 정도·활성도·합/충 맥락 |
| W1 | \`WELLNESS:BALANCE\` · \`ELEMENT:*\` · \`STRENGTHS\` · \`ATTENTION_AREAS\` · \`HABITS\` | 오행 기반 생활 참고 정보 |
| W2 | \`WELLNESS:LIFETIME_CONTEXT\` | 대운 중 주의 구간(현재 상위 3개 추출) |
| C1 | \`CHILD:BOND\` · \`PARENTING_STYLE\` · \`STRENGTHS\` · \`ATTENTION_AREAS\` | 자녀 인연과 양육 관계의 상징 |
| C2 | \`CHILD:LIFETIME_CONTEXT\` | 자녀 관계와 겹치는 일부 대운 구간 |
| X1 | \`CONTEXT:RELATIONSHIP_STATUS\` · \`CONTEXT:CHILD_REALITY_UNKNOWN\` | 사용자 상황(현재 자녀 데이터는 UNKNOWN) |
| **F2 추가 필요** | \`FORTUNE:SEUN-*\`, \`FORTUNE:WOLUN-*\` | 연운·월운 \`synthesis\`와 간지/기간 맥락 |
| **F3 추가 필요** | \`CATEGORY:*\` | 분야별 \`wealth/business/career/relationship/study\` 도움과 활성도 |
| **N8 추가 필요** | \`NATAL:SAMJAE\` | 기존 \`analysis.samjae\`는 있으나 LIFETIME evidence에 미포함 |
| **X2 추가 필요** | 연령/시간 참조, 자녀 유무 등의 **명시적** 고객 입력 | 실제 경험을 추측하지 않고 제목 분기 |
| **N9 보강 필요** | 월령·조후·강약 계산의 **세부 증거** | 현재 N3/N4/Y2는 요약 중심, 상세 이론을 설명하려면 원계산 하위 팩트가 필요 |

> **표기:** 아래 \`주\`는 이 주제에서 반드시 우선 검토할 주근거, \`보조\`는 실제 관련성이 확인된 경우만 쓰는 근거. Y1/Y2/F1을 등장시킨다고 문장마다 용신·대운을 언급하라는 의미는 아니다.

## E. 코드에서 반드시 수정해야 할 연결점

1. \`src/rules/lifetime-report.v2.ts\`: 고정 18장 대신 V5.6의 PART/소제목 정의로 교체 **또는 새 버전 파일로 병행**. 구버전 삭제 금지.
2. \`src/lib/saju/ai-interpretation/input-builder.ts\`: 지금 \`switch(section.id)\`가 18장만 분기함. V5.6의 **소제목 단위 evidenceIds**로 빌드하도록 변경. \`NATAL:SAMJAE\`, F2, F3, 고객 문맥(X2) 공급 추가.
3. \`src/lib/saju/ai-interpretation/prompt.ts\`: '01~18장' 고정 문구 제거, **소제목별 핵심 질문과 근거 우선순위** 전달.
4. \`src/lib/saju/ai-interpretation/grounding.ts\`: 신규 reportPlan 고정 순서·허용 근거 범위와 고객별 가변 제목 검증. 값이 없을 때 생성 거부/조건부 분기.
5. \`src/lib/saju/ai-interpretation/service.ts\`: 비용·지연·중복을 줄이도록 전체 100+ 소제목을 한 번에 호출하지 말고 PART별 생성 + 선행 PART 요약 상태 공유 + 최종 전체 검수 설계.
6. \`src/lib/saju/ai-interpretation/schema.ts\`: 'PART → 소제목' 계층, 가변 연운/대운, 실제 인용 evidence IDs를 표현하게 확장.
7. \`src/lib/saju/ai-interpretation/grounding.ts\`에 중복 검사: 동일한 문단이 서로 다른 소제목에서 반복되면 불합격. 문법용 접속 오류도 테스트 대상으로 추가.
8. \`WELLNESS:LIFETIME_CONTEXT\`는 지금 관심도 상위 3개 대운만 전달함. 청년·중년·노년의 전기간 해설에는 **시기 범위를 빠짐없이 연결**해야 함.
9. \`CONTEXT:CHILD_REALITY_UNKNOWN\`가 항상 unknown임. 임신·출산/자녀/손주 장의 맥락 분기는 별도의 명시적 고객 입력이 필요함. **기혼 여부로 자녀 존재를 추정하면 안 됨**.
10. PART02~04에 현재 하나의 WORK 집합을 재활용하는 경로가 있다면 **직업 적성/학업, 조직·승진, 자영업·운영**으로 섹션별 근거를 분리해야 함.

## F. 승인 테스트 (해설 생성 전에)
